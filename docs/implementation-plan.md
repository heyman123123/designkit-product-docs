## 1. 关键架构决策

### 1.1 前端采用「零构建」方案（本次决策）

- 本机运行环境只有 Node 单二进制，**没有 npm**；引入 Next.js 会新增一整套工具链与 CI 依赖。
- 因此 Web 工作台、管理后台、移动端 PWA 统一使用 **原生 ES Module + 共享设计系统 CSS**，由 Go 通过 `embed.FS` 直接托管：
  - 一个二进制 = API + Web 工作台 + 管理后台 + PWA，部署零额外步骤；
  - 没有 node_modules、没有构建产物漂移，CI 只需要 `go test`；
  - 视觉与交互仍然按 UI 设计稿实现（设计 token、响应式、状态矩阵）。
- 后续若要上 Next.js/SSR，接口契约不变，前端可平滑替换，不影响后端与部署。

### 1.2 路由与托管

```
/                → 302 /app/
/app/#/...       → Web 工作台（用户端，hash 路由）
/admin/#/...     → 管理后台（独立令牌、独立入口）
/m/              → 移动端 PWA
/v1/*            → Go API
/healthz         → 健康检查
```

### 1.3 前端 API 契约

所有请求走 `web/assets/core.js` 的 `api` 模块：
- 自动带 `Authorization: Bearer`；
- 401 时用 refresh_token 静默换新并重放一次，失败则回登录页；
- 统一错误结构 `{error:{code,message}}`；
- 租户接口统一 `/v1/w/{slug}/...`。

### 1.4 版本模型

新增 `asset_versions` 表：一个 SKU 的一个模板槽位（main/scene/selling_point）下可以有多条版本；
`is_current` 标记当前主版本；导出只取当前主版本；驳回后重新生成产生新版本，旧版本保留可回滚。

### 1.5 计费

MVP 走「平台后台人工开通 + 配额字段」：套餐变更、试用延长、订单/发票登记都在后台完成；
支付网关（Stripe/支付宝）留 `billing` 接口与 webhook 占位，不阻塞上线。

## 2. 阶段规划

### P0 · 规划与骨架（本次）
- [x] 全功能清单与阶段划分（本文）
- [x] 前端设计系统与共享核心（`web/assets/`）
- [x] Go 静态托管与 SPA 回退
- 验收：`/app/`、`/admin/`、`/m/` 可访问，未登录跳登录页，刷新 404 不出现。

### P1 · Web 工作台主链路
页面：登录/注册、工作台首页、项目、项目详情（文件夹树 + SKU 列表）、SKU 详情（素材、生成、结果、版本）、审核队列、导出、用量、设置、成员。
- 上传（拖拽 + 多选 + 进度 + 失败重试）
- 生成（模板选择、幂等键、SSE 进度、失败原因展示）
- 审核（通过 / 驳回必填原因 / 批量）
- 导出（ZIP 下载、额度不足提示）
- 验收：新注册账号能在 5 分钟内走完「建项目 → 建 SKU → 传图 → 生成 → 审核 → 导出」全流程，页面无白屏、无控制台报错。

### P2 · 版本链与 QC 明细
- `asset_versions` 模型 + 接口 + UI（版本列表、对比、设为主版本、回滚）
- QC 规则：分辨率、长宽比、白底占比、透明通道、文字/水印风险（可配置阈值）
- 生成结果写 `qc_issues`（JSON），前端展示问题项与修复建议
- 验收：同一 SKU 同一模板至少 3 个版本可切换；QC 问题项可见。

### P3 · 管理后台（运营端）
- 租户：列表 / 详情 / 套餐与配额调整 / 暂停恢复 / 重置 owner
- 订阅：套餐定义、订单、发票备注、试用延长、优惠码
- 成本：按租户 / 模板 / 天聚合，毛利与成本占比告警
- 任务：失败队列、单条/批量重试、取消、死信
- 风控：待审队列、投诉冻结、封禁
- 配置：模型供应商、平台规则版本、模板上下架、feature flags
- 审计日志
- 验收：运营不碰数据库即可完成「开通客户、调额度、查成本、重试失败任务、封禁租户」。

### P4 · 移动端 PWA
- 拍照 / 相册选图 → 上传 → 生成 → 进度 → 审核 → 分享
- 离线草稿提示、安装到桌面、移动端安全区适配
- 验收：手机浏览器完成一次「拍照上传 → 审核通过 → 分享链接」。

### P5 · 真实 AI 供应商与存储
- `PROVIDER=mock|openai-compatible`：图像生成 + 视觉分析，超时/重试/错误分类/成本记账
- `STORAGE_DRIVER=local|s3`：S3 兼容（R2/MinIO），SigV4 预签名直传
- 验收：切换 env 即可对接真实模型与对象存储，mock 仍可跑测试。

### P6 · 计费闭环与上线
- 套餐/额度/订单/发票模型，试用与到期降级
- 支付网关占位 + 后台人工开通
- Docker 生产编排、CI、健康检查、备份说明
- 文档站同步本规划与接口变更
- 验收：可对外提供一个真实可注册、可付费开通的站点。

## 3. 团队分工

| Bot | 职责 | 文件边界 |
| --- | --- | --- |
| 服务端工程 | Provider（真实模型）、S3 存储、队列可靠性、相关单测 | `apps/api/internal/{service,storage,config}`，只新增文件，不改 handler/router/main |
| 后台工程 | 管理后台前端（P1 → P3 后台部分） | `web/admin/**` |
| 移动端工程 | 移动端 PWA | `mobile/**` |
| Chief（我） | 规划、Web 工作台、后端业务接口、静态托管、集成、验收、发布 | 其余全部 |

约束：Bot 不执行 `git commit/push`；不跨目录修改；交付前必须本地跑通自己范围内的检查。

## 4. 风险与回退

| 风险 | 应对 |
| --- | --- |
| 真实模型 API 不可用 / 无 Key | mock provider 保持默认，切换只改 env，链路不阻塞 |
| 前端零构建代码膨胀 | 按模块拆分 `pages/*.js`，共享 core；单文件不超过 ~500 行 |
| 多人并行改同一仓库冲突 | 文件边界写死，Bot 不碰 Go 路由；我统一集成提交 |
| 配额/计费漏洞 | 所有扣减走事务 + usage_ledger 不可变流水，测试覆盖 |
| 跨租户越权 | 所有查询带 `workspace_id`，集成测试固定 6 个接口 + 资产内容 |
