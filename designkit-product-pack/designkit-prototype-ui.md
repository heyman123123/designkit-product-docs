# DesignKit 需求原型与 UI 设计规格（最终交付版）

> 版本：v0.2（MVP）  
> 适用端：Web 生产管理端、App 采集与审核端  
> 依据：[DesignKit PRD](./designkit-prd.md)；技术架构文档当前未随资料包提供，本文不新增超出 PRD 边界的复杂能力。

## 1. 产品边界与设计原则

### 1.1 MVP 主流程

`Workspace → Project → Folder → SKU → Asset → AssetVersion`  

端到端路径：

`创建项目 → 创建 SKU/文件夹 → 上传原图 → 自动分析 → 确认分析 → 生成图片 → QC → 人工审核 → 高清导出`

Web 负责批量生产、配置、管理和导出；App 负责拍摄/上传、任务进度、审核、备注与只读分享，不复制完整编辑器。

### 1.2 原则

1. 图片优先：工作区用中性背景，缩略图保持统一比例，避免装饰性 UI 抢占注意力。
2. 状态可追溯：每个 AssetVersion 显示原图、分析结果、模型/提示词、操作者、时间和审核记录。
3. 异步可恢复：上传、分析、生成、QC、导出均有 loading、进度、失败、重试、取消和刷新恢复。
4. 操作可逆：归档、驳回、回滚等优先软删除/版本回退；危险操作必须确认。
5. 不以颜色为唯一状态表达：颜色 + 文案 + 图标/符号同时表达。
6. 桌面优先生产，移动端优先审核；首屏始终保留一个明确主 CTA。

## 2. 信息架构与路由

### 2.1 Web 路由

| 路由 | 页面职责 | 主 CTA |
|---|---|---|
| `/dashboard` | 项目概览、任务、配额、最近活动 | 新建项目 |
| `/projects/:projectId` | 项目内文件夹树、SKU、资产网格 | 上传图片 |
| `/projects/:projectId/sku/:skuId` | SKU 资产、分析、生成与审核上下文 | 生成图片 |
| `/tasks` | 上传/分析/生成/QC/导出任务队列 | 重试失败任务 |
| `/assets` | 跨项目资产检索（MVP 仅基础筛选） | 打开资产 |
| `/qc/:taskId` | QC 检查项、风险与处理结果 | 通过并送审 |
| `/exports` | 导出记录、进度、下载 | 创建导出 |
| `/settings` | 账户、Workspace、配额/计费入口 | 保存设置 |

上传、分析和生成采用项目内 Drawer/Sheet，不新增独立路由，保证用户不丢失当前 SKU 上下文。

### 2.2 App 路由

| Tab/页面 | 职责 |
|---|---|
| 任务 | 今日待审核、进行中、失败任务 |
| 项目 | 最近项目、SKU 与只读浏览 |
| 上传 | 相机/相册、多图队列、断点续传 |
| 我的 | 账户、通知、分享记录 |
| 审核详情 | 全屏图片、左右切换、通过/需修改/备注 |
| 分享详情 | 只读项目/SKU/版本信息，过期后不可访问 |

- 文件夹最多两级：SKU/批次；禁止创建第三级。
- 网格卡显示缩略图、状态徽标、版本号、QC 状态、失败原因摘要。
- 多选后出现批量工具条；批量破坏性操作须二次确认。
- 服务端版本冲突：保留本地未提交输入，提示“内容已在其他设备更新”，提供查看最新/覆盖（有权限时）。

### 3.4 上传与分析 Drawer

```text
Step 1 上传 → Step 2 分析 → Step 3 确认
┌─────────────────────────────────────┐
│ 上传到：项目 / SKU / 批次       [×]  │
│ [拖拽上传区域] [选择文件] [相机导入]  │
│ 支持 JPG/PNG/WebP · 单文件大小提示    │
│ 文件队列：                            │
│ ✓ image-01.jpg  已上传               │
│ … image-02.jpg  上传 68% [取消]       │
│ ! image-03.heic 格式不支持 [重试]     │
│                              [继续]    │
└─────────────────────────────────────┘
```

分析完成后展示：主体、颜色、材质、属性、OCR、卖点建议、平台规格建议、风险标签。字段可编辑，修改标记“人工修订”；原图始终保留。

规则：
- hash 去重：重复文件显示“已存在于当前 SKU”，不新建 Asset，可选择查看原资产。
- 批量上传 20 张时显示成功/失败汇总；失败项可单独重试。
- 分析失败不阻断资产查看；提供“重试分析”和“跳过分析（不可进入自动生成）”。
- 关闭 Drawer 不取消任务；再次打开可恢复到当前步骤。

### 3.5 生成配置与确认

```text
生成图片
输入版本：AssetVersion v3（可查看原图/分析）
类型： (●)白底主图  ( )生活场景图  ( )卖点图
模板： [Amazon 主图标准 ▼]
数量： [-] 4 [+]       站点：[Amazon US ▼]
预计消耗：SKU 配额 1 · 高清余额 0
[查看规则]                         [取消] [确认生成]
```

- 同一 SKU 存在生成中任务时，“确认生成”禁用并链接到当前任务。
- 提交前必须展示预计扣费；提交后显示幂等任务编号。
- 配额不足：按钮禁用，文案说明缺口，并提供购买/升级入口；不创建半成品任务。
- 重复点击提交只生成一个任务、不重复扣费。

### 3.6 结果工作台

```text
SKU-001 / 结果                         [版本 v3 ▼] [原图对比]
[全部] [待审核] [已通过] [需修改] [QC失败]     [批量通过] [导出]
┌结果卡┐ ┌结果卡┐ ┌结果卡┐ ┌结果卡┐
│图片   │ │图片   │ │图片   │ │图片   │
│v1     │ │v2     │ │v1     │ │v3     │
│QC通过 │ │需修改 │ │审核中 │ │失败   │
│□      │ │□      │ │□      │ │□      │
└───────┘ └───────┘ └───────┘ └───────┘
```

- 点击卡片打开详情 Sheet：大图、原图对比、版本选择、分析摘要、生成参数、审核记录。
- 通过/驳回必须记录操作者与时间；驳回必须填写原因（预设原因 + 可选备注）。
- 回滚仅创建指向旧版本的新当前指针，不删除历史版本。
- 批量操作仅作用于当前筛选结果中的已选项，并在提交前显示数量。

### 3.7 QC 页

检查项：尺寸、背景、主体完整性、文字、Logo/敏感风险、清晰度。

```text
左：图片预览/放大/原图对比       右：QC Checklist
                                   尺寸       ● Pass
                                   背景       ● Review
                                   主体       ● Pass
                                   文字       ● Reject + 原因
                                   Logo风险   ● Pass
                                   清晰度     ● Pass
                                   [保存检查] [通过并送审]
```

- `Reject` 必须有原因；`Review` 进入人工确认，不得直接高清导出。
- 任一检查项为 Reject/Review 时，导出按钮禁用并解释阻断原因。
- 自动 QC 结果可人工覆盖，但必须标记覆盖人、时间和理由。

### 3.8 导出中心

```text
导出新任务
选择项目/SKU/版本 [筛选]   导出类型：普通 / 高清（需余额）
将导出 8 张，规格：Amazon US v1
[取消] [创建导出]

导出记录：文件名 | 范围 | 状态 | 创建人 | 创建时间 | 有效期 | 下载
```

- 创建后显示排队/处理中进度；失败支持重试，不重复扣费。
- 下载采用短期签名 URL；过期后展示“链接已过期”，可重新生成，不直接暴露永久地址。
- 未通过 QC 的图片不出现在可选列表中。

## 4. App 线框与交互

### 4.1 首页/任务

```text
今日待审核 3                         [通知]
[拍摄上传] [查看进度]
最近项目
[项目卡] [项目卡]
待审核图片（2 列网格）
底部：任务 | 项目 | 上传 | 我的
```

### 4.2 拍摄/上传

相机/相册 → 选择多图 → 预览与删除 → 选择项目/SKU/批次 → 上传队列 → 断点续传 → 任务编号。

- 权限拒绝提供去系统设置入口；无权限不循环弹窗。
- 弱网显示暂停/继续；App 退后台后任务继续或恢复。
- 每张图显示上传状态，失败项单独重试；hash 去重与 Web 端一致。

### 4.3 审核详情

```text
[返回] SKU-001  3/8                         [查看原图]
                 全屏图片
[上一张]                           [下一张]
[通过] [需修改] [添加备注]
```

左右滑动切图，底部操作栏固定；“需修改”必须填写原因，可保存草稿。Web 与 App 共享最终审核状态，冲突时以服务端版本为准并提示。

### 4.4 只读分享

分享链接展示项目、SKU、版本、图片和审核状态；无编辑/导出权限。过期、撤销、无权限分别显示明确状态与返回入口，不暴露资源是否存在以外的敏感信息。

## 5. 状态矩阵

| 对象 | 正常 | 加载/进行中 | 成功 | 失败 | 可恢复动作 |
|---|---|---|---|---|---|
| 项目 | 可打开 | 同步中 | 已同步 | 权限/网络失败 | 重试、返回 |
| 上传 | 待上传 | 百分比/队列 | 已上传 | 格式/大小/网络 | 单项重试、删除队列 |
| 分析 | 待分析 | 分析中 | 可编辑结果 | 分析失败 | 重试、查看原图 |
| 生成 | 可提交 | 任务编号/进度 | 结果可审核 | 配额/风控/模型失败 | 升级、重试、查看原因 |
| QC | 待检查 | 自动检查中 | Pass | Review/Reject | 查看原因、人工覆盖 |
| 审核 | 待审核 | 提交中 | 通过/需修改 | 保存失败 | 重试，保留本地输入 |
| 导出 | 可创建 | 排队/处理中 | 可下载 | 失败/过期 | 重试/重新生成链接 |

通用空态：说明当前原因 + 一个主 CTA；通用错误：可读原因 + 重试 + 联系支持（如适用）；所有异步状态使用 `aria-live`，不只依赖颜色。

## 6. 响应式规则

### 6.1 断点与布局

| 视口 | 框架 | 网格 | 交互规则 |
|---|---|---|---|
| ≥1280px | 左侧栏 240px，内容区最大 1440px | 结果 4–6 列 | Drawer 480px；详情可双栏 |
| 768–1279px | 侧栏收为抽屉，内容边距 24px | 3–4 列 | 配置表单改 Sheet；工具条允许换行 |
| ≤767px | 顶部简化，底部导航 56px | 2 列 | 上传/配置用全屏 Sheet；审核全屏 |

### 6.2 通用规则

- 页面水平内边距：桌面 24–32px，平板 24px，手机 16px。
- 图片缩略图固定比例（建议 1:1 或由资源类型配置），使用 `object-fit: cover`；详情图 `contain`。
- 手机底部主操作栏避让安全区；触控目标最小 44×44px。
- 表格在手机改为卡片列表，不要求横向滚动完成关键操作。
- 移动端筛选/排序集中在 Bottom Sheet；关键主 CTA 固定在可见区域。
- 侧栏收起后保留图标 + tooltip，并保证键盘可达。

### 7.3 状态与反馈

### 7.4 关键组件输入/输出

| 组件 | 必要输入 | 关键输出/事件 |
|---|---|---|
| `UploadQueue` | 文件、hash、状态、进度、错误 | retry、cancel、remove、completed |
| `AnalysisSummary` | 分析字段、置信度、风险、可编辑性 | change、save、retry |
| `GenerationForm` | 模板、站点、数量、配额、busy 状态 | submit、cancel、openQuota |

## 8. 视觉 Token 与可访问性

### 8.1 Token

```text
字体：Inter, system-ui, -apple-system, sans-serif
正文 14px/22px；辅助 12px/18px；区块标题 16px/24px；页面标题 24px/32px
间距基线 4px：控件 8/12px，卡片 16px，页面 24px，区块 24/32px
圆角：控件 8px，卡片 12px，弹窗 12px
```

颜色使用语义 Token，不在组件内硬编码：`--color-primary`、`--color-success`、`--color-warning`、`--color-danger`、`--color-bg-muted`、`--color-border`、`--color-text`。文本与背景满足 WCAG AA；暗色主题仅在主题层配置。

### 8.2 可访问性

- 所有输入有可见 Label；错误与帮助文本通过 `aria-describedby` 关联。
- Drawer/Dialog 打开后焦点进入标题或首个控件，关闭后回到触发元素；Esc 关闭非破坏性浮层。
- 键盘可完成上传、筛选、选择、审核、确认；焦点样式可见。
- 状态徽标同时包含文字；进度更新使用 `aria-live="polite"`，错误使用 `role="alert"`。
- 图片有替代文本；仅装饰图使用空 alt；对比视图提供可读的版本信息。

## 9. 可开发验收标准

### 9.1 流程验收

- [ ] 用户在 Web 端 5 个主要动作内完成：创建项目 → 创建 SKU → 上传 → 选择模板 → 提交生成。
- [ ] 端到端流程可完成：上传 → 分析 → 确认 → 生成 → QC → 审核 → 高清导出。
- [ ] 刷新页面、切换设备、重新进入路由后，层级和任务状态不丢失。
- [ ] 同一 SKU 生成中不可重复提交；幂等请求不重复扣费。

### 9.2 数据与权限

- [ ] 资产卡可追溯输入版本、模型、提示词、操作者、时间、审核记录。
- [ ] 非 Workspace 成员无法读取项目、资产、任务和导出链接。
- [ ] 归档/删除采用软删除；回滚不抹除历史版本；审计日志保留关键操作。
- [ ] Web/App 上传、任务、审核状态最终一致；冲突提示服务端版本。

### 9.3 异常与状态

- [ ] 上传 20 张图片成功率目标 ≥95%；失败可单项重试；重复 hash 不创建重复资产。
- [ ] 分析失败保留原图；生成失败、网络失败、导出失败均可重试。
- [ ] 配额不足时禁止提交并提供购买/升级入口；风控拦截显示可理解原因。
- [ ] QC 任一项为 Reject/Review 时无法进入高清导出；Reject 必须填写原因。
- [ ] 导出链接过期后不可下载原链接，可重新生成短期链接。

### 9.4 视觉与可访问性

- [ ] ≥1280、768–1279、≤767 三档布局按本文规则实现，无核心操作被遮挡。
- [ ] 触控目标 ≥44×44px；键盘可完成主要 Web 流程；焦点不丢失。
- [ ] 异步状态有骨架/进度/文案，错误有重试；颜色不是唯一状态表达。
